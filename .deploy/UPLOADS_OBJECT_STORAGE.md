# Uploads → Object Storage Runbook (Cloudflare R2)

All image uploads (product images, custom-request reference sketches, profile
pictures) go through `backend/Services/storageService.js`. Two backends exist:

| `STORAGE_BACKEND` | Where files go | Use for |
|---|---|---|
| `local` (default) | `backend/uploads/*`, served at `/uploads/*` by the API | development; or a host with a persistent disk |
| `s3` | any S3-compatible bucket (Cloudflare R2, AWS S3, B2, MinIO…) | production on an ephemeral host (Render, etc.) |

The `s3` backend is implemented with Node's built-in `crypto` + `fetch` (no SDK).
Its SigV4 signature is pinned to AWS's reference signer in
`backend/tests/storageS3.test.js`.

## Security properties (both backends)

- Every upload is validated from its **bytes** (`utils/imageValidator.js`):
  JPEG / PNG / GIF / WebP only, no SVG, header dimensions ≤ `MAX_IMAGE_DIMENSION`
  (8192). Invalid files are deleted from temp storage, never stored.
- Keys are generated by the server: `products/<ownerId>-product-<uuid>.<ext>`,
  `references/<ownerId>-reference-<uuid>.<ext>`, `profiles/<name>`. The
  extension comes from the sniffed format. Only these three prefixes are
  accepted (`assertKeySafe`).
- Delete is owner-or-admin only (`routes/uploadRoute.js`).
- The bucket credentials stay on the API server. The browser never talks to
  the R2 API; it only loads public image URLs.
- AI try-on **results are never put in this bucket** — the public bucket
  domain would expose them. They stay in the private result store
  (`AI_TRYON_RESULT_DIR`, see `AI_TRYON_OPERATIONS.md`).

## Setting up Cloudflare R2

1. **Create the bucket** (Cloudflare dashboard → R2 → Create bucket), e.g.
   `kente-media`. Location: automatic.
2. **Give it a public domain** (bucket → Settings → Public access):
   - Preferred: **Custom domain**, e.g. `media.yourdomain.com` (Cloudflare
     caching, your own hostname).
   - `r2.dev` subdomain works for testing but Cloudflare rate-limits it and
     does not recommend it for production.
   The whole bucket becomes publicly readable through that domain — store only
   files that are meant to be public (the three prefixes above are).
3. **Create an API token** (R2 → Manage API tokens → Create): permission
   **Object Read & Write**, scoped to **this bucket only**. Copy the Access Key
   ID and Secret Access Key (shown once). Do not use an account-wide token.
4. **CORS: not needed.** Images are loaded with plain `<img>` tags and the
   upload goes browser → API → R2. (The only canvas use in the frontend is the
   customer's own try-on photo, which never comes from R2.)
5. **Set the API server's environment** (Render dashboard / host secret store —
   never in git, never in a `VITE_` variable):

   ```
   STORAGE_BACKEND=s3
   S3_ENDPOINT=https://<ACCOUNT_ID>.r2.cloudflarestorage.com
   S3_BUCKET=kente-media
   S3_REGION=auto
   S3_ACCESS_KEY_ID=<token access key id>
   S3_SECRET_ACCESS_KEY=<token secret>
   S3_PATH_STYLE=true
   S3_PUBLIC_BASE_URL=https://media.yourdomain.com
   # Product images on R2 are absolute https URLs; the try-on garment fetcher
   # only reads remote hosts on this allow-list:
   AI_TRYON_ALLOWED_HOSTS=media.yourdomain.com
   ```

   Boot checks: with `STORAGE_BACKEND=s3` the API **exits at startup** if any
   of the four required `S3_*` values is missing, and in production also if
   `S3_PUBLIC_BASE_URL` is not an `https://` URL (the R2 API endpoint itself is
   not publicly readable, so every image would be broken).
6. **Run the preflight** on the production environment:
   `node scripts/staging-preflight.mjs --target=production`
   — it fails on the same conditions without printing any secret.
7. **Smoke test after deploy**: as a vendor, upload a product image → the
   returned URL starts with `S3_PUBLIC_BASE_URL` → it opens in a private
   browser window with `Content-Type: image/jpeg|png|webp|gif` → delete it →
   it disappears from the bucket (it may stay in Cloudflare's cache for up to
   an hour: objects are written with `Cache-Control: public, max-age=3600`, the
   same policy as local `/uploads`).

## Existing files on local disk

Rows that already reference `/uploads/...` keep working only while those files
exist on the API host. The API serves a placeholder image for missing
`/uploads/*` files. If the database is being reset for launch this does not
matter; otherwise copy `backend/uploads/{products,references,profiles}` into the
bucket under the same keys and rewrite the stored URLs to `S3_PUBLIC_BASE_URL`.

## Env knobs

| Variable | Default | Meaning |
| --- | --- | --- |
| `STORAGE_BACKEND` | `local` | `local` or `s3`; anything else exits at boot |
| `S3_ENDPOINT` | — | `https://<account>.r2.cloudflarestorage.com` |
| `S3_BUCKET` | — | bucket name |
| `S3_REGION` | `auto` | R2 always uses `auto` |
| `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | — | bucket-scoped R2 API token |
| `S3_PATH_STYLE` | `true` | keep `true` for R2 |
| `S3_PUBLIC_BASE_URL` | — | public bucket domain; required (https) in production |
| `S3_TIMEOUT_MS` | `30000` | per-request deadline to the bucket |
| `MAX_IMAGE_DIMENSION` | 8192 | pixel cap enforced from image headers |
